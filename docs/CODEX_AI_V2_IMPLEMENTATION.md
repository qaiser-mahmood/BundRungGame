# Codex implementation contract: AI v2

Repository: qaiser-mahmood/BundRungGame
Working branch: feature/ai-v2-ismcts
Starting point: feature/advanced-strategic-ai (Phase 2 experimental policy)
PR target: feature/advanced-strategic-ai, unless that branch has already been merged into main, in which case target main.
DO NOT merge automatically. DO NOT change the live default from corrected-search.

## Goal and acceptance
Implement the complete proposed v2 architecture in coordinated, reviewable commits. Do not claim superior strength without held-out paired-match evidence. Existing authoritative engine remains sole source of game rules and scoring. Existing corrected-search and advanced-search must continue working. No changes to canonical neural checkpoint.

## 0. Inspect before implementation
Read BundRungEngine, ScoringEngine, SimulationWorld, MonteCarloPlanner, WorldSampler, CardTracker, BotPlayer, DecisionPolicy, LivePolicy, Phase 2 report, benchmark harness, neural schema/checkpoint. Map all game states and transitions, especially hidden trump selection, face-down plays, reveal/challenge, accumulated tricks, individual opponent consecutive-win rule after reveal, Ace downgrade, final trick, KHOTI and dealer-relative scoring. Document a rule parity inventory and invariants.

## 1. Compact simulation engine (server/ai/v2/simulation)
Implement CompactState, FastSimulator, adapters, and RuleParity tests. Use compact cards and efficient hands, but benchmark BigInt masks against two Uint32 masks or typed arrays before choosing. Avoid expensive JSON cloning, full observation serialization, or repeated authoritative-engine reconstruction in the hot loop. Represent ALL gameplay state necessary to preserve exact legal actions, forced actions, reveals, trick resolution, terminal scoring and match outcomes. Never silently approximate rules. Make RNG injectable and state cloning explicit. Do not expose hidden hands to decision policy. Add seeded differential tests against BundRungEngine at every transition, including hard edge cases, mid-trick reconstruction and terminal scores; run >=10,000 representative reachable transitions plus targeted rare-rule fixtures. Compare legal cards, turn actor, reveal eligibility, trick winner, phase and official scoring. A parity mismatch blocks search integration. Keep authoritative engine as safe fallback.

## 2. Beliefs (server/ai/v2/beliefs)
Implement BeliefState, ParticleSampler, OpponentLikelihood. Reuse constraint-preserving sampler initially; optimize only with correctness evidence. Keep hard facts (known ownership, voids, disclosures, private remembered concealed cards) separate from soft probabilities. Do not mistake losing a trick or declining to overtake for hard evidence. Optional weighted particles: use observed opponent actions under a plausible behavior model, normalize log weights, calculate effective sample size, resample/rejuvenate, detect particle impoverishment. Evaluate calibration (Brier/log loss where meaningful), diversity, constraint violations and sampling cost on seeded simulated deals. Handle opponent-policy mismatch; compare weighted vs uniform baseline. No cross-room or cross-player private-state caches.

## 3. Information-set search (server/ai/v2/search)
Implement ISMCTS with information-set-consistent nodes and action-availability counts (including legal actions that differ across sampled worlds). Tree selection (e.g. UCT/PUCT) must not expose sampled hidden ownership to an actor's decision. Re-determinize at simulated actor turns or use another explicitly justified information-set method; explain residual strategy fusion/nonlocality. Shared legal action masks, legal fallback, determinism with seeded RNG, complete-simulation atomic statistics, explicit node/iteration/deadline caps, no accidental global Math.random mutation. Reward = authoritative team hand/match outcome, not arbitrary trick count. Implement affordable rollout policy using existing partnership heuristic as a baseline, with ablations. Track root action visits, estimated value, belief diversity, invalid worlds, fallbacks, deadline stops and per-decision time.

## 4. Hybrid controller and endgames (server/ai/v2/strategy)
DecisionController routes forced/obvious decisions cheaply, uncertain consequential positions to ISMCTS, and genuinely public fully determined small endgames to exact team minimax. Never use perfect-information sampled hands as if they were public. Allocate computation by estimated value-of-computation, uncertainty, legal branching and remaining time, not merely trick number. Keep total live computation soft-budgeted at 25 ms initially. Respect RoomTurnQueue; benchmark 8, 16 and 32 rooms, queue wait and event-loop delay. Existing corrected-search remains fallback on simulation parity failures or internal search errors.

## 5. Learning pipeline (server/ai/v2/learning)
Implement policy/value training infrastructure AFTER validating search strength. Capture observation-only features, legal masks, search visit distributions, authoritative terminal rewards, versioned schema and reproducible seeds. Never train on actual hidden cards as network inputs. Support isolated experimental checkpoint paths, resume validation, atomic writes, checkpoint hashes and strict prohibition on canonical checkpoint overwrite. Start with small supervised imitation from search; evaluate policy-only inference and neural-guided search separately. If teacher is not demonstrably stronger, keep training experimental and report this honestly. No heavy dependencies without evidence and approval.

## 6. Policy integration and benchmarking
Add experimental policy name ai-v2-ismcts to DecisionPolicy and server-controlled LivePolicy opt-in, retaining corrected-search default and advanced-search. Never accept policy selection from unauthenticated client payload. Preserve baseline behavior. Build controlled paired-deal comparisons: corrected-search, advanced-search, v2 without weighted beliefs, v2 with weighted beliefs, v2 with/without partnership rollouts, v2 with/without adaptive controller, and neural-guided if trained. Compare at matched wall-clock budgets as well as fixed-work budgets, and report both separately. Use disjoint development and held-out seeds; do not reuse Phase 2 held-out 200000–200999 as a fresh holdout. Run 50 pairs smoke, 200 development, then >=1000 held-out pairs after freezing parameters when feasible. Report paired bootstrap CIs, official signed score, invalid/aborted games, per-policy compute and queue latency, calibration and search diagnostics. Benchmark full multi-hand matches separately from one-hand games when possible. Avoid overinterpreting noisy small differences.

## 7. Gates, documentation and delivery
Add tests for information isolation (swap real hidden hands without changing actor observation), per-room independence, rule parity, terminal scoring, forced reveals, Ace downgrade, consecutive wins, reproducibility, deadline and safe fallback, exact public endgame eligibility, model persistence safety. Run npm ci, npx tsc --noEmit, npm run typecheck:ai, npm test, npm run build, benchmark:tactics, parity suite, latency and tournaments. Include raw benchmark JSON and concise docs/AI_V2_ARCHITECTURE.md and docs/AI_V2_EVALUATION.md with commands, version hashes, all regressions and limitations.

Use logical commits: simulator/parity; beliefs; ISMCTS; hybrid; learning; integration; evaluation. Avoid huge generated artifacts in git (summaries plus reproducible scripts). Push branch and open a draft PR. Do not merge or promote to default. If scope or performance forces a tradeoff, prioritize exact simulator parity and fair ISMCTS experiments; report unfinished modules rather than fake completion.

Promotion bar: demonstrably stronger than corrected-search on fresh held-out paired outcomes (prefer >=55% wins and paired 95% interval excluding 50%), no material regression in official score, legality, latency or room responsiveness. A failure to meet this bar is a valid experimental outcome, not permission to cherry-pick seeds.
